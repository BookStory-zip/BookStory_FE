# 서재·타이머 화면 정리

사용자 승인: 대화에서 1~6번 결정안을 승인하고 구현을 요청했다. 이후 책장 목록의 앞·뒤 버튼도 제거하기로 했다.

## 확정 범위

1. 서재 검색은 기본 접기. 데스크톱에서는 검색·필터·관리를 같은 상단에 두고 모바일에서는 검색/필터·정렬/관리로 압축한다. 검색·상태·책장 조건과 해제는 펼침 여부와 무관하게 노출한다. 관리 메뉴에서 책장 관리·순서 편집·책 선택에 진입한다.
2. 실제 열 수와 목록에 쓸 수 있는 높이로 초기 조회량을 정하고 렌더링 뒤 부족분을 보충한다. 일부 보이는 마지막 행도 채운다. 크기 변경·검색 접기 후 재검사한다. 요청당 limit 1~100, offset은 받은 수 기준. 부족하면 종료, 오류면 자동 반복 없이 수동 재시도. BE 기본 20과 API 계약은 변경하지 않는다.
3. 책장 관리는 별도 모달. 생성·이름 변경·순서 변경·삭제, 저장 후 서버 확인과 불명확한 결과의 재확인을 보존한다. 저장·재확인 중 닫기/Esc 금지. 모바일 내부 스크롤, 포커스 복귀. 삭제 확인에서 책은 남고 연결 정보는 사라짐을 알린다.
4. 책과 책장 모두 반복되는 앞·뒤 버튼 제거. 손잡이 드래그와 방향키 이동, 손잡이 클릭으로 앞/뒤 한 칸 이동 메뉴 제공. 이동마다 저장하며 기존 실패 복구와 결과 확인을 보존한다. 필터 중 책 순서 편집 금지 유지.
5. 타이머 측정이 기본. 작은 시간 기록 보기로 기록을 펼친다. 기록 안에서 모든 상태의 책을 골라 조회·삭제할 수 있다. 기록 선택/접기가 측정 책·타이머를 변경하지 않는다. 삭제 확인과 독서 체크 보존 안내 유지.
6. 서재·책장 관리·타이머의 반복 설명과 분위기 부제 삭제. 사용법은 해당 영역의 접이식 도움말. 오류 원인·삭제 영향·공개 범위·현재 조작 제한의 이유는 필요한 상황에 유지.

## 선택과 제약

- 상단 버튼을 모두 노출하는 안보다 검색과 관리 접기를 선택: 모바일 첫 화면의 책 공간 확보.
- 고정 20권 후 보충만 하는 안보다 가변 초기 조회와 보충을 선택: 큰 화면의 왕복 요청 감소.
- 기존 React/CSS/네이티브 dialog와 API를 재사용. 새 의존성, BE 변경, 다른 화면 전면 개편 없음.
- 네 작업은 같은 작업 공간의 순차 브랜치로 쌓는다. main 병합·원격 push는 별도 요청 없이 하지 않는다.
- 실제 기기의 스크린리더 검증은 자동화만으로 대체할 수 없으며 최종 보고에 한계를 명시한다.

## 수용 조건

390/768/1440px에서 가로 넘침 없음. 접힌 검색 조건 해제 가능. 보이는 행에 책이 남아 있으면 빈칸 보충. 100권 초과·검색 변경 중 늦은 응답·오류 반복·책 부족 종료 검증. 모달과 이동 메뉴 키보드/포커스/저장 잠금 검증. 기록을 접어도 측정과 저장 복구 유지.
