# 백엔드 API 연동

FE가 사용하는 BookStory BE API 계약과 FE 반영 방식, BE 전달 사항입니다.
구현 전에는 BE `app/` 코드와 운영 [OpenAPI](https://bookstory-api-w31a.onrender.com/openapi.json)를 다시 대조합니다.
BE가 FE용으로 정리한 계약은 BE 저장소 `docs/frontend-api.md`에 있습니다.

- 운영 API: https://bookstory-api-w31a.onrender.com · [Swagger](https://bookstory-api-w31a.onrender.com/docs)
- 기준: BE 5차 main `e4aec03`(2026-11-05 사용자 전달: 서재 정렬·도서 검색 기준/정렬·계정 알림·과거 읽은 날 운영 반영), FE main `97a039c`(PR #21, 2026-11-04 자동 운영 배포). BE 5차 verify·운영 OpenAPI·로그인 점검 통과는 BE 회신이며, FE가 운영 인증 API나 Render 배포 SHA·DB를 직접 확인한 것은 아닙니다. 실제 FE 확인 범위는 plan.md에 기록합니다.

## 인증

Supabase SDK로 로그인·세션 복원 → `session.access_token`으로 `GET /me` 성공 → 개인 화면을 엽니다.

- BE에는 `/login`·`/signup`이 없습니다. 요청은 `Authorization: Bearer <access_token>`만 씁니다.
- 401은 SDK로 한 번만 갱신해 다시 요청합니다. 503·연결 실패·60초 시간 초과는 로그아웃으로 처리하지 않습니다.
- 계정이 바뀌면 개인 화면을 새로 그려 이전 계정의 늦은 응답을 버립니다.
- 401 재시도는 최초 요청과 같은 사용자일 때만 허용합니다. 갱신 전·후에 계정이 바뀌거나 로그아웃됐으면 이전 동작을 재전송하지 않습니다.
- 세션 없는 가입 성공은 이메일 인증 대기입니다. 재설정 메일은 `/reset-password/update`로 돌아옵니다.

## 책 찾기 검색 기준·정렬 (2026-11-05, BE develop 계약 기준)

- `GET /books/search?query=&page=&target=&sort=`의 선택 `target`은 `title`(제목)·`person`(저자·역자)·`publisher`(출판사)이며 생략하면 전체입니다. `sort`는 `accuracy`(기본, 정확도순)·`latest`(출간일 최신순)입니다. 카카오 순서를 그대로 쓰며 출간일이 같은 항목의 순서는 보장하지 않습니다. 잘못된 값은 422 `validation_error`입니다.
- 기존 documents·isbn13·meta.is_end·페이지당 10건·최대 50페이지를 유지합니다. FE는 ISBN13 없는 결과를 숨기되 다음 페이지 여부와 페이지 번호는 원래 응답으로 판단합니다.
- FE는 검색 전에 고른 조건을 첫 요청에 사용합니다. 검색 이후 조건 변경은 마지막으로 제출한 검색어로 1페이지부터 다시 조회하며, 입력 중인 미제출 검색어는 바꾸지 않습니다. 화면에 실제 적용된 검색어·기준·정렬을 표시하고 더 보기는 그 요청의 조건을 유지합니다. 새 결과는 누적 목록·숨긴 권수를 교체하며 이전 검색·더 보기의 늦은 응답은 버립니다.
- 기본 검색은 기존 URL과 정확도순을 유지하고 429 대기 중에는 조건 선택도 잠급니다. 서재 안의 제목·저자 검색은 별도 기능으로 그대로 둡니다. 실제 BE/카카오 연동·운영 반영은 이번 가짜 API 기반 로컬 검증과 구분합니다.

## 개인 독서 통계

`GET /me/statistics?year=2026&month=10`은 월간, `month`를 생략하면 연간 합계입니다.

- `library`: 기간과 무관한 현재 서재 현황(`total_books`, 5개 상태의 `status_counts`, `completed_books`). 완독 경험은 재독 중인 책도 포함하고 회독 횟수를 세지 않습니다.
- `period`: 선택 기간 활동(`year`, 연간이면 null인 `month`, `start_date`, `end_date`, `reading_days`). 같은 날 여러 책을 체크해도 1일이며, 체크 취소·서재 삭제 후 수치가 달라질 수 있습니다. 타이머 API 반영 버전에는 `reading_minutes`가 추가됩니다(아래 독서 타이머 계약 참고).
- FE: 통계 탭은 달력과 선택 월을 공유하고, 연간·월간 전환과 이전 기간 이동을 지원합니다. 기간을 바꾸거나 화면을 떠나면 이전 응답을 버리고, 오류·로딩·실제 0일을 구분합니다. 12개월 추이 그래프는 없습니다.
- 상태: BE main `290da3e` 배포 후 사용자가 연간·월간 통계 조회 200과 서재 합계를 확인했습니다. FE 실제 운영 브라우저 통합 검증은 별도입니다.

## 책 상세와 공개 후기

- FE `/catalog/{isbn13}`에서 책 정보·내 기록·후기를 동시에 독립 조회합니다. 개인 편집은 기존 `/books/{user_book_id}`를 재사용합니다.
- 개인 상세의 `is_review_public`, `review_published_at`, `review_updated_at`은 필수 응답 필드입니다. 누락을 false로 보정하지 않습니다.
- 공개를 선택해 저장한 메모와 별점만 공개됩니다. 빈 메모 공개는 422 `review_memo_required`이며, 공개 후 메모 삭제는 비공개 전환입니다. 메모를 다시 입력해도 자동 공개하지 않습니다.
- 공개 해제는 개인 메모·별점을 보존합니다. 별점·메모 수정은 공개 후기에도 반영됩니다. 상태·중단 사유는 공개되지 않습니다.
- 저장 후 개인 상세를 다시 조회하고 공통 상세로 이동하면 집계·후기를 새로 조회합니다. 공유 캐시·브라우저 저장소에 개인 응답을 보관하지 않습니다.
- 공개 후기 순서는 공개 시각·ID 내림차순입니다. 편집 시 순서는 유지하고 다시 공개하면 순서가 바뀔 수 있습니다. 실시간 변경 중 offset 페이징의 누락 가능성은 BE 계약을 따르며, 중복 표시는 제거합니다.
- 서재 삭제 시 공개 후기도 삭제됩니다. 완독 경험 없는 읽고 싶음 초기화는 메모·별점·공개 상태도 지우고, 완독 경험이 있으면 보존합니다.

## 독서 상태와 날짜

| 상태 | 규칙 |
| --- | --- |
| `want_to_read` 읽고 싶음 | 되돌리면 시작일·중단일·사유 초기화. 완독 경험이 없으면 완독일·별점·메모도 초기화 |
| `reading` 읽는 중 | 읽고 싶음·완독·포기에서 오면 새 독서: 시작일을 미리 채우지 않고 빈칸이면 오늘 시작. 중단에서 재개·읽는 중 날짜 고치기는 기존 시작일 유지 |
| `completed` 완독 | 읽는 중·중단에서 오면 완독일 생략 시 지금. 완독일 null 가능. 재독을 시작해도 이전 완독일 보존 |
| `paused` 중단 | 읽는 중에서만 |
| `abandoned` 포기 | 읽는 중·중단에서만 |

- 사용자가 고른 날짜만 `started_date`·`completed_date`로 보냅니다. BE가 시작은 KST 00:00, 완독은 KST 23:59:59(오늘이면 서버 현재 시각)로 저장합니다.
- `started_date`·`completed_date`는 서버 KST 오늘 이후, `started_at`·`completed_at`은 서버 현재 시각 이후면 422 `future_date`로 거부하며 기존 기록은 바뀌지 않습니다. 허용 오차는 없고 오늘 완독·날짜 생략/null·날짜 순서·상태 전환 규칙은 유지합니다. FE는 날짜 필드만 보내며 `detail` 문자열 대신 `code`로 안내합니다. 날짜 선택기의 기기 기준 오늘 제한은 보조 수단이며 최종 판단은 서버가 합니다. BE main `1ffaa8a` 운영 반영·실제 미래 시작일 거부와 FE 운영 화면에서 오늘/어제 날짜 시작·완독 저장 후 새로고침 유지까지 사용자가 2026-11-02 확인했습니다. 미래 완독일·자정 경계의 실제 API 검증은 남아 있습니다.
- 고를 수 있는 상태는 상세의 `allowed_statuses`를 따릅니다. 현재 상태는 읽는 중·완독일 때 날짜 고치기용으로만 고릅니다.
- `read_date`·`published_date`는 문자열 그대로 다뤄 시간대 변환으로 하루가 밀리지 않게 합니다.
- 중단 7일 경과 포기와 도서 정보 갱신은 BE 배치 몫이며 FE 타이머로 처리하지 않습니다.

## 사용성 개선 FE 작업 (2026-11-05, 기존 API 재사용)

- 서재는 `limit/offset`을 유지해 무한 스크롤로 조회합니다. 최초 화면이 덜 차면 다음 페이지를 이어 받고, 드래그·순서 저장·책장 쓰기·결과 확인 중과 추가 조회 오류 후에는 자동 조회를 중지합니다. 순서 저장 후 이미 불러온 범위 전체를 100권 이하 요청으로 나눠 동시에 재조회하고, 앞 구간이 짧게 오면 뒤 구간은 버립니다.
- 책장 담기·빼기는 상세에서 제거하고 서재 선택 모드로 옮깁니다. 기존 책장 PUT·DELETE를 선택한 개인 서재 ID마다 호출하며, 일부 성공은 보존하고 실패·결과 불명확을 구분합니다. 처리 후 목록과 서버 책장 권수를 다시 조회하고, 확인 실패 시 재확인 전 추가 쓰기를 막습니다.
- 측정·시간 기록은 상세에서 `/timer`로 이동합니다. 측정용 목록은 `status=reading`을 끝까지 조회하며, 시간 기록 모드는 전체 상태의 책을 선택해 기존 조회·삭제 API를 사용합니다. 로컬 측정과 세션 저장 계약은 유지합니다.
- 책 찾기는 응답의 `isbn13=null` 문서를 FE에서 숨기고, 숨긴 권수를 담을 수 없는 이유와 함께 안내합니다. 다음 페이지 판단은 원래 `meta.is_end`·최대 50페이지를 사용하며, 필터 후 0건이어도 다음 페이지가 있으면 더 보기를 제공합니다. 기존 API 응답은 변경하지 않습니다.
- 서재 카드 제목 끝의 괄호 하나만 표시에서 제거하되 숫자·(상)(중)(하)·(N권)·(제N권)·(Vol. N) 같은 권 표시는 남기고 원문을 보존합니다. 중단·포기는 서재 필터 선택지에서만 숨기며 API 상태 값은 유지합니다.
- 별도 BE 계약인 서재 정렬·도서 검색 기준/정렬·계정 알림·과거 읽은 날은 이 FE 작업에 연결하지 않습니다. BE의 기능별 배포 및 최종 계약 확인 후 후속 작업으로 연결합니다.

## 서재 정렬 (2026-11-05 수용 계약, FE 구현·운영 연동 확인 대기)

- `GET /library/books`의 선택 `sort`: `custom`(기본)은 `position ASC, created_at DESC, id DESC`, `created`는 `created_at DESC, id DESC`, `started`는 `started_at DESC NULLS LAST, created_at DESC, id DESC`입니다. 조회만 바꾸고 저장된 position은 유지합니다. 기존 응답·limit/offset·검색/상태/책장 조합은 유지하며 잘못된 값은 422 `validation_error`입니다.
- FE는 정렬 변경 시 offset 0부터 다시 받고, 모든 추가 페이지·필터 변경·책장 작업 후 재조회에 선택 정렬을 유지합니다. 위치 편집은 custom이면서 검색·상태·책장 필터가 없을 때만 허용합니다. 정렬 422는 이전 조건으로 복귀하고 검색어 대신 정렬 선택에 안내합니다.
- FE 구현은 전달받은 확정 계약 기준입니다. BE 5차 main `e4aec03` 운영 반영 완료 안내를 받았습니다(2026-11-05). FE의 운영 OpenAPI 접근은 실패했으며 실제 인증 API 연동 검증은 남아 있습니다.

## 계정 알림 최종 계약 (BE 5차 main `e4aec03`, 2026-11-05)

- `GET /me/reminder-settings` → `{enabled: boolean}`, `PUT /me/reminder-settings {enabled: boolean}` → 204입니다. 필수 boolean 누락·null은 422 `validation_error`, 미인증은 401입니다.
- **구독 PUT·DELETE는 저장된 계정 설정을 바꾸지 않습니다.** 구독 PUT이 true를 켠다는 중간 전달 계약을 대체합니다. 설정을 저장한 적 없는 계정은 구독 여부를 따르며, GET에서 true를 읽으면 서버가 그 값을 저장해 이후 마지막 구독이 사라져도 켜짐을 유지합니다. 신규 계정은 구독이 없어 false입니다.
- `enabled=false`이면 모든 기기 발송을 막습니다. FE의 끄기는 설정 PUT만 보내며, 기기 구독을 지우지 않습니다. 로그아웃은 현재 기기의 구독만 해제하고 계정 설정은 유지합니다.
- FE 계정 화면에서 전역 켜짐과 현재 기기 수신 상태를 구분합니다. 지원하지 않거나 권한이 차단된 기기에서도 계정 설정을 바꿀 수 있고, 권한 요청은 별도 버튼을 누를 때만 합니다. 기록 화면은 설정 화면으로 연결합니다.
- 로그인·앱 복귀 시 설정이 true이고 권한이 granted일 때만 자동 구독합니다. 다른 계정·주인 불명 구독은 설정 조회 성공 여부와 관계없이 먼저 끊습니다. 설정·기기 변경은 순서대로 처리하고 계정 변경·이탈 뒤 늦은 쓰기를 막습니다. 권한 창은 이 대기열을 막지 않습니다.
- 저장 결과 불명확·기기 등록 실패 시 재전송하지 않고 계정 상태를 재조회합니다. 재조회 실패는 꺼짐으로 표시하지 않고 재확인 버튼만 제공합니다.

## 가져온 책의 과거 읽은 날 (BE 5차 main `e4aec03`, 2026-11-05)

BE `docs/frontend-api.md`와 `app/reading_logs.py`·`schemas.py`를 대조했습니다. 운영 반영은 사용자 전달이며 FE의 운영 인증 API 쓰기는 확인하지 않았습니다.

- 개인 상세 두 경로의 필수 `past_log_range`: 완독이고 완독일(KST)이 KST 오늘 - 7일 이하인 책만 `{start: "YYYY-MM-DD" | null, end: "YYYY-MM-DD"}`(양 끝 포함, start null은 하한 없음, end는 완독일), 아니면 null입니다. FE는 null이면 영역을 숨기고, 상태·날짜로 범위를 추정하지 않습니다.
- 하루씩은 기존 `PUT·DELETE …/reading-logs/{read_date}`를 범위 안 날짜에도 씁니다. 범위 밖 오래된 날짜는 PUT 422 `date_too_old`·409 `reading_check_not_allowed`, 취소는 422 `date_too_old`입니다. 범위가 바뀌어도 기존 기록은 지우지 않고 범위 밖 기록은 고칠 수 없습니다.

- 쓰기 결과와 관계없이 다시 보내지 않습니다. 성공·404·409·`date_too_old`·결과 불명확 시 그 달 기록과 상세(`past_log_range`·`last_read_date`)를 재조회하고, 재조회 실패 시 재확인 전 쓰기를 막습니다. 실패 시 기간 입력은 보존합니다. 달력·통계는 진입할 때 새로 조회합니다.

## 지난 날짜 독서 체크 (운영 반영)

BE `feat/past-reading-check` `26903f5` 제공 안내와 로컬 코드·`docs/frontend-api.md`를 대조했습니다(2026-11-03). 운영 반영과 실제 연동 확인 범위는 plan.md에 별도로 기록합니다. 이 날짜 API 변경에는 스키마 변경·DB migration이 없습니다.

- 날짜는 서버 KST 오늘부터 6일 전까지 포함합니다. PUT은 현재 읽는 중인 책만 가능하며 현재 시작일 이전 날짜면 409 `date_order`입니다. 이미 체크한 날짜는 시작일이 뒤로 바뀌어도 기존 기록을 200으로 돌려주지만, 현재 읽는 중이 아니면 기존 체크에도 PUT은 409입니다.
- DELETE는 같은 날짜 범위에서 상태와 무관하게 가능하고 기록이 없어도 204입니다. 범위 검사는 상태보다 먼저 하며 미래는 422 `future_date`, 7일 전부터는 422 `date_too_old`, 형식 오류는 422 `validation_error`입니다. 실패는 기존 체크·상태·완독일을 바꾸지 않습니다.
- `created_at`은 실제 체크 요청 시각이고 활동 날짜는 `read_date`입니다. 개인 상세 두 경로의 필수 nullable `last_read_date`는 가장 최근 읽은 날짜입니다. 최근 날짜의 체크를 취소하면 남은 최신 날짜 또는 null이 됩니다. FE는 누락을 `last_read_at`으로 보정하지 않습니다.
- FE는 선택한 날짜의 실제 로그와 모든 서재 페이지를 조회합니다. 체크된 책에는 상태와 무관하게 취소 버튼, 미체크인 읽는 중 책에는 체크 버튼을 보여 줍니다. 시작일 검사를 FE에 복제하지 않습니다. 완료 기록만 있는 책은 체크된 것으로 간주하지 않습니다.
- 저장·재조회 중 중복 변경을 잠그고 성공·409·404·결과 불명확 시 날짜별 목록과 월 달력을 다시 조회합니다. 재조회 실패 시 이전 결과를 유지하고 최신 체크 확인 전 쓰기를 막습니다. 통계는 탭을 열 때 새로 조회합니다.
- FE 검증 → BE 병합·운영 배포 → FE 배포 순서입니다. 기존 `/today`는 유지하지만 날짜 경로·`last_read_date`를 쓰는 FE를 BE보다 먼저 배포하지 않습니다.

## 독서 타이머 (2026-11-04 확정, 운영 반영)

BE PR #25의 `docs/frontend-api.md`·구현과 사용자 회신을 대조했습니다. 시계 오차 5분 허용·계정 내 세션 겹침 거부까지 반영한 계약입니다.

| API | 계약 |
| --- | --- |
| `POST /library/books/{user_book_id}/reading-sessions` | `{client_session_id: UUID, started_at: 시간대 포함 ISO, duration_seconds: 정수 60~3600}`. 신규 201, 같은 책·시각·시간의 같은 ID 재전송 200 |
| `GET /library/books/{user_book_id}/reading-sessions?limit=20&offset=0` | 배열, 시작 시각 DESC·id DESC. limit 1~100 |
| `DELETE /reading-sessions/{session_id}` | 204, 독서 체크는 남김 |

- 세션 응답은 `{id, user_book_id, client_session_id, started_at, duration_seconds, read_date, created_at}`. 시작 시각의 KST 날짜를 사용하며 자정을 넘겨도 나누지 않습니다.
- 세션과 해당 날짜 독서 체크는 같은 트랜잭션입니다. 읽는 중·최근 7일·독서 시작일 이후 규칙을 통과해야 저장하며, 이미 체크돼 있으면 유지합니다. 서재 삭제·탈퇴는 연결된 세션도 삭제합니다.

- 시작·끝 시각이 서버 현재 시각보다 5분을 넘게 앞서면 각각 422 `future_date`·`invalid_duration`. 그 밖에 422 `date_too_old`·`validation_error`, 409 `reading_check_not_allowed`·`date_order`, 미인증 401·없는/타인 항목 404입니다.
- `/me/statistics.period.reading_minutes`는 선택 기간에 시작한 세션 초를 모두 합한 뒤 분으로 내림합니다(90초 두 개는 3분). FE는 서버 값을 사용합니다.

- 저장 전 종료 시간과 ID를 고정합니다. 결과 불명확·409 등 실패 시 보관하고 직접 재시도하게 하며 자동 재전송하지 않습니다. 겹침은 "이미 기록된 시간과 겹칩니다"로 안내합니다. 로그아웃·계정 변경은 측정을 정리하고 늦은 응답으로 복원하지 않습니다. 다른 책의 측정도 확인 후 버릴 수 있어 삭제된 책의 측정 때문에 막히지 않습니다.

## 읽기 진도 (2026-11-09 BE 회신 확정, 운영 반영 전)

BE 회신(2026-11-09)으로 확정한 계약입니다. BE 브랜치 코드와 운영 OpenAPI는 아직 직접 대조하지 않았습니다. 운영 반영은 목표 일괄 저장과 함께 하며, FE는 그 뒤에 배포합니다.

| API | 계약 |
| --- | --- |
| `GET /library/books`, `GET /library/books/{id}`, `GET /library/books/by-isbn/{isbn13}` | 필수·nullable `page_count`·`total_pages`·`current_page`·`progress_percent` |
| `GET /books/{isbn13}`(공개) | 필수·nullable `page_count` |
| `PATCH /library/books/{id}/progress` | `{current_page?, total_pages?}` → 200 `{id, page_count, total_pages, current_page, progress_percent}`. 생략은 그대로, null은 지우기 |

- `page_count`: 책이 처음 등록될 때 BE가 국립중앙도서관 ISBN 서지정보에서 한 번 가져온 쪽수(본문+부록, "1,024 p." → 1024). 여러 권 묶음("2책")이나 없는 책은 null이며, 정기 갱신으로 바뀌지 않습니다(2026-11-09 BE 리뷰 반영). 키는 BE 환경에만 둡니다.
- 전체 쪽수 = `total_pages` ?? `page_count`. `progress_percent`는 완독 100, 읽고 싶음 null, 전체 쪽수나 현재 쪽이 없으면 null, 그 외 floor(current_page / 전체 쪽수 × 100)이며 100을 넘지 않습니다.
- 검사는 반영 후 값으로 합니다. `total_pages` 1~99999, `current_page` 0~전체 쪽수. 전체 쪽수가 없는데 현재 쪽을 보내거나, `total_pages`를 지워 기준이 사라지거나 현재 쪽보다 작아지는 경우도 422 `page_out_of_range`(영어 문자열 `detail`, `loc` 없음)이며 아무것도 바뀌지 않습니다. 정수가 아닌 값은 422 `validation_error`.
- `total_pages`는 모든 상태에서, `current_page`는 읽는 중·중단·포기에서만 바꿀 수 있습니다. 읽고 싶음·완독에서 `current_page`를 보내면 409 `progress_not_allowed`. 완독에서 `total_pages`를 바꾸면 현재 쪽을 새 전체 쪽수로 맞춥니다. 타인·없는 항목 404, 미인증 401.
- 상태 전환: 읽고 싶음 초기화, 재독(완독 → 읽는 중), 다시 시작(포기 → 읽는 중, 2026-11-09 BE 리뷰 반영)은 현재 쪽을 지우고 전체 쪽수를 유지합니다. 완독 전환은 전체 쪽수를 알면 현재 쪽을 맞춥니다. 재개(중단 → 읽는 중)와 읽는 중·중단 → 포기는 유지합니다.
- 제외(다음 단계): 날짜별 진도 이력, 기간별 읽은 쪽수 통계, 쪽수로 읽은 날 자동 체크.
- FE: 상세의 읽기 진도 카드에서 전체 쪽수와 현재 쪽(쪽 또는 %)을 입력합니다. %는 반영 후 전체 쪽수로 반올림해 쪽으로 보내며, 전체 쪽수를 모르면 고를 수 없습니다. `page_out_of_range`에 칸 위치가 없으므로 같은 규칙으로 먼저 검사하고(`src/lib/progress.ts`) 바뀐 칸만 보냅니다. 422는 입력을 그대로 두고, 409·결과 불명확은 다시 보내지 않고 상세를 다시 불러옵니다. 서버 진도 값이 바뀌면 입력을 새 값으로 맞춥니다. 서재 카드는 완독이 아닌 책에 %를 붙이고, 공개 책 정보에 쪽수를 표시합니다.

## 서재 검색·상태 필터 (D-1, 2026-11-04 합의, 운영 반영)

BE 사전 합의 확정 회신(2026-11-04) 기준이며 BE `9ca25e1`에서 실제 연동을 확인했습니다(plan.md). BE는 D-1을 D-2(책장)와 따로 먼저 검증 환경에 올리고, 운영 반영은 C·D-1·D-2를 함께 합니다.

- `GET /library/books?q=&field=title|author&status=&limit=20&offset=0`. 대소문자를 구분하지 않는 포함 검색이며 `%`·`_`도 글자 그대로 찾습니다. 저자는 이름 하나하나에서 찾고, `field` 생략 시 title입니다.
- q는 앞뒤 공백 제거·NFC 정규화 뒤 코드 포인트 최대 200자(넘으면 422 `validation_error`, detail 배열), 정규화 전 원문도 1000자까지(BE 추가 통보), 공백만이면 422 `blank_query`(문자열 detail). 검색어를 지우면 q를 빼고 보냅니다. q 없는 field는 무시하고 허용하지 않는 field 값은 422입니다.
- q·field·status(·D-2의 shelf_id)는 함께 적용되고 정렬은 저장된 서재 순서, 전체 개수 헤더는 없습니다. 대소문자 무시는 DB 기준(영문·악센트 등 유니코드 대소문자, ß↔ss 같은 확장 변환 없음, 운영 DB 확인 후 확정).
- FE: 서재 화면에 제목/저자 선택·검색어·검색 버튼·검색 해제·읽기 상태 선택을 둡니다. 서버가 조건을 422로 거부하면 이전 조건으로 돌아가 입력란에 안내합니다. q를 모르는 BE는 전체 서재를 돌려주므로 FE는 BE 운영 반영 뒤에 배포합니다. q는 FE도 같은 규칙으로 먼저 검사해 공백만·200자 초과를 요청 전에 막고, 검색어가 있을 때만 field를 보냅니다. 조건이 바뀌면 offset 0부터 다시 조회하고 이전 조건의 늦은 응답을 버립니다. 결과 0건과 오류를 구분하고, 더 보기 실패 시 결과와 다음 offset을 유지합니다. 필터가 있으면 서재 순서 편집을 막고, 편집 중에는 조건을 바꾸지 않습니다. 불러온 일부 책으로 로컬 검색하지 않습니다.

- 서재 상태 필터 요청(2026-11-03 FE 수용): `GET /library/books?status=reading&limit&offset`. `status`는 선택·5개 상태 중 하나, 생략 시 전체, 저장된 서재 순서·기존 응답 형식 유지, 잘못된 값 422 `validation_error`. 체크 편집기가 이 필터로 요청하되, 필터를 모르는 서버가 전체를 돌려줘도 화면에서 다시 `reading`만 고르므로 BE 배포 순서와 무관하게 안전합니다.
- 켜기 여부는 위 계정 알림 설정을 따릅니다. 같은 endpoint를 다시 PUT하면 키만 갱신하고, 다른 계정이 같은 endpoint를 등록하면 그 계정으로 옮깁니다. DELETE는 본인 구독만 지우며 없어도 204입니다.
- BE는 404·410과 저장된 키를 쓸 수 없는 구독만 삭제합니다. 발송 키 교체 뒤 이전 키 구독의 403은 실패로만 세고 지우지 않습니다.
- FE: 계정 화면에서 알림을 켜고 끄며, 별도 기기 권한 버튼에서만 권한을 요청합니다. 서버 등록이 실패하면 브라우저 구독을 남기지 않습니다. 로그아웃은 DELETE 결과와 무관하게 브라우저 구독을 해제하며, 서버에 남은 구독은 다음 발송의 410으로 정리됩니다.
- 계정 보호: 구독한 계정을 브라우저 저장소에 기록합니다. 로그인·앱 복귀 시 다른 계정·주인 불명·권한 회수 구독은 먼저 끊고 현재 계정 설정을 확인합니다. 켜짐·권한 granted일 때 기존 구독을 재등록하거나, 구독이 없으면 새로 만듭니다. 공개 키가 바뀌면 이전 endpoint를 DELETE하고 다시 구독합니다.
- 503은 "지금은 알림을 사용할 수 없어요"로 안내하고 로그아웃하지 않습니다. 미지원 브라우저에는 iOS 16.4 이상 홈 화면 추가 안내와 계정 설정 버튼을 보여 줍니다. endpoint는 로그·화면에 출력하지 않습니다.
- 서비스 워커는 요청을 가로채거나 캐시하지 않습니다. `/sw.js`는 `Cache-Control: no-cache`로 배포하고, 로그인·앱 복귀 시 기존 워커의 update를 확인합니다. 새 워커는 skipWaiting·clients.claim으로 활성화하며 열린 FE 페이지를 강제로 새로고침하지 않습니다. manifest는 홈 화면 추가용 최소 구성입니다.

## 계정·안정성 (공개 가입 전, 운영 반영)

BE와 2026-11-03 확정했습니다. BE 2차 운영 반영 완료 안내 뒤 FE main `d066516`으로 배포했습니다. 검증 환경의 실제 데이터 쓰기와 운영 읽기 전용 확인은 plan.md에 구분해 기록합니다.

- 탈퇴 `DELETE /me`: 서재·개인 기록·공개 후기·독서 체크·알림 구독/발송 기록·Supabase 로그인 계정을 바로 삭제하고 공통 책 정보는 남깁니다. 유예 기간은 없습니다. BE는 JWT `amr`의 password 인증 시각이 5분 이내인지 보며, 토큰 갱신으로는 바뀌지 않습니다. 서비스 데이터를 먼저 지우고 로그인 계정을 지우며, 같은 요청을 다시 보내면 이어서 처리합니다(여러 번 보내도 안전). 503 뒤 재시도하지 않고 다시 로그인하면 빈 계정으로 보입니다.
  - FE: `/settings` 탈퇴 → 영향 범위 안내·확인창 → 비밀번호 재입력 → 현재 계정 이메일로 `signInWithPassword` → 같은 계정인지 확인한 새 토큰으로 `DELETE /me`. 204면 알림 해제·로컬 로그아웃 후 로그인 화면에 완료 안내. 로그아웃이 늦거나 실패해도 계정 화면에 완료를 남기고 다시 보내지 않습니다. 403·503·비밀번호 오류는 로그아웃하지 않고 안내하며, 결과가 불명확하면 자동 재전송하지 않고 사용자가 다시 시도하게 합니다. 결과가 불명확했거나 재시도의 재로그인이 비밀번호 오류면 Supabase `getUser`의 `user_not_found`로 로그인 계정이 이미 지워졌는지 확인해 완료로 처리합니다.
- 닉네임 `GET·PATCH /me/profile`: 앞뒤 공백 제거·NFC 정규화 뒤 2~20 코드 포인트, 완성형 한글·영문·숫자·`_`·`-`와 한 칸 공백만(자모·연속 공백 불가). 중복 허용, 빈 문자열은 422. 공개 후기 `author_name`에 바로 반영되며 FE 표시 수정은 없습니다.
  - FE: 같은 규칙으로 먼저 검사하고 정규화한 값을 보냅니다. 입력을 비우면 null을 보냅니다. 서버 응답 값으로 화면을 갱신하고, 결과가 불명확하면 입력을 둔 채 확인을 안내합니다.
- 요청 수 제한: `GET /books/search` 분당 30회(IP), `GET /books/{isbn13}` 60회(IP), `POST /library/books` 30회(사용자). 429 `rate_limited`와 `Retry-After`(초). 운영 IP는 Render 프록시 단계 수(`TRUSTED_PROXY_HOPS`)로 판별합니다.
  - FE: 검색·더 보기 429는 `Retry-After`(없거나 비어 있으면 60초) 동안 검색 버튼과 더 보기를 막고, 받은 시점의 대기 초를 안내합니다(카운트다운 없음). 차단은 검색 화면을 나갔다 와도 이어지고, 끝나면 안내를 지웁니다. 담기 429는 "요청이 많아 서재에 담지 못했습니다"로 저장되지 않았음을 알립니다. 자동 재시도는 하지 않습니다.
- 처리되지 않은 오류는 500 `internal_error`로 통일하고 모든 응답에 `X-Request-ID`를 붙입니다. CORS가 가장 바깥에서 동작해 429·500에도 CORS 헤더가 붙고, `Retry-After`·`X-Request-ID`는 `expose_headers`로 읽을 수 있습니다. FE는 X-Request-ID를 이번에는 표시하지 않습니다.
- `last_read_at`은 응답에 그대로 남습니다(가장 최근 체크 시각으로 계산, 없으면 null). FE는 필수 필드로 검사만 하고 화면에는 쓰지 않습니다.

## 서재 순서 변경 계약 (운영 반영)

BE가 제시한 204 응답과 `invalid_position` 코드를 포함해 아래 계약을 FE에서 수용합니다(2026-11-02). 기존 공통 API는 204에서 JSON을 읽지 않습니다. BE `728f8e2` 구현과 로컬 검증 API를 대조했고, 검증 계정 A/B로 실제 로그인·이동·새로고침 유지·21권 페이지 경계·같은 브라우저 계정 전환을 확인했습니다. 이후 BE main `2c2b6e7`·FE main `a82c21a` 운영 반영을 확인했습니다. 운영 계정의 실제 순서 이동·새로고침 저장 유지는 아직 검증하지 않았습니다.

- `PATCH /library/books/{user_book_id}/position`, 본문 `{ "after_user_book_id": "바로 앞에 둘 서재 항목 UUID" }`. 필드는 필수이며 `null`이면 맨 앞으로 이동합니다. 생략은 422 `validation_error`입니다. 경로와 본문의 ID는 모두 개인 `user_book_id`입니다.
- 성공은 본문 없는 204입니다. 이미 같은 위치인 요청도 204로 처리합니다.
- 미인증은 401, 이동 대상·기준 항목이 없거나 다른 계정 소유면 404 `Library book not found`입니다. 기준 항목이 자기 자신이면 422 `invalid_position`입니다. FE에서는 자기 자신·동일 위치 이동 요청을 만들지 않고 해당 코드에 한국어 안내를 표시합니다. 404는 최신 목록을 다시 조회합니다.
- BE는 본인 서재 전체 순서에서 기준 항목 바로 뒤로 이동해 순서를 저장하며, 조회하지 않은 페이지의 책을 보존합니다. `GET /library/books`는 저장된 순서로 기존 limit·offset을 유지하고 응답 필드를 추가하지 않습니다. FE가 숫자 순위를 계산하거나 전체 ID 배열을 보내지 않습니다.
- 기존 책의 초기 순서는 최신 등록순 유지, 신규 등록은 맨 앞입니다. 기존 책 재등록(200)은 위치를 바꾸지 않습니다. 이동은 개인 상세 `updated_at`을 바꾸지 않고 상태·기록·독서 체크 변경은 순서에 영향을 주지 않습니다. 삭제 후 나머지 책의 순서는 유지합니다.
- 같은 사용자의 이동·등록은 순서대로 처리합니다. 기준 항목의 위치는 실제 처리 시점 기준이며 나중에 처리된 이동 결과가 남습니다. 다른 계정의 순서는 바뀌지 않습니다.
- FE는 불러온 책 사이에서 마우스·터치 손잡이 드래그와 앞/뒤 버튼(키보드 가능) 이동을 지원합니다. 드래그 중 화면 가장자리에 닿으면 자동 스크롤하고, Escape는 손잡이 포커스와 관계없이 드래그를 취소합니다. 이동마다 저장하며 성공 후 offset 0부터 불러온 개수(최대 100개)를 한 번에 다시 조회합니다. 저장·재조회 중 이동·더 보기를 잠그고 결과 불명확 시 쓰기를 자동 반복하지 않습니다. 재조회 실패 시 기존 목록을 유지하고 "최신 순서 다시 확인" 성공 전 추가 이동을 막습니다. 이동 후 해당 손잡이, 다시 불러온 범위 밖이면 편집 버튼, 재조회 실패 시 재확인 버튼으로 포커스를 복구합니다.
- 반영 순서는 FE 검증 → BE PR·develop·main 반영 → 운영 DB migration `57f75310c7d5` → BE 운영 배포 → FE 운영 배포입니다. 검증 DB의 migration 적용은 BE 전달 사항이며 운영 DB 적용 완료로 해석하지 않습니다.
